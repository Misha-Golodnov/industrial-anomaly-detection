# Industrial Anomaly Detection

Проект по обнаружению неисправных состояний промышленных систем с использованием методов машинного обучения и анализа многомерных временных рядов.

Разрабатывается в рамках магистерской программы «Инженерия искусственного интеллекта».

## Цель проекта

Исследовать возможности адаптации методов классификации временных рядов к задаче **одноклассового поиска новизны (Novelty Detection)**.

## Датасет

Используется **Tennessee Eastman Process (TEP)** — датасет, полученный при компьютерном моделировании промышленного химико-технологического процесса.

В проекте применяется расширенная версия Rieth et al. (2017).

Основные характеристики:

- 52 технологических параметра: 41 измеряемая и 11 управляющих переменных.
- 20 типов моделируемых неисправностей.
- 500 обучающих прогонов нормальной работы по 500 временных отсчётов.
- Отдельные тестовые наборы нормальных и неисправных состояний.
- Формат исходных данных — `.RData`.

Источник: [Additional Tennessee Eastman Process Simulation Data for Anomaly Detection Evaluation](https://doi.org/10.7910/DVN/6C3JR1).

Исходные файлы датасета размещаются в `data/raw/` и не включаются в Git-репозиторий.

Нужны четыре файла: `TEP_FaultFree_Training.RData`, `TEP_FaultFree_Testing.RData`, `TEP_Faulty_Training.RData`, `TEP_Faulty_Testing.RData`.

Разведочный анализ данных представлен в ноутбуке `notebooks/01_eda.ipynb`.

Проверка кода:

```bash
python -m unittest discover -s tests
```

## Код эксперимента

Пакет `industrial_novelty` готовит одни и те же окна для всех моделей. Модель видит массив формы `(число окон, длина окна, число каналов)` и возвращает одну оценку на окно: чем она больше, тем сильнее новизна.

- Обучение — нормальные обучающие прогоны. Порог выбирается по отложенной части этих прогонов. Ложные срабатывания считаются на `TEP_FaultFree_Testing`.
- Разрез только по `simulationRun`.
- В неисправном тесте окно, пересекающее 160-й отсчёт, выбрасывается. Метка отказа стоит у окна, которое целиком начинается с 161-го отсчёта.
- Окна после аварийного останова помечены в паспорте и не засчитываются как обнаружение отказа.
- Отчёт добавляет долю нормальных прогонов с тревогой, устойчивость тревоги, долю ранних обнаружений, запас до останова и AUROC по каждой неисправности.
- Масштаб каналов считается по обучающим отсчётам и затем применяется к остальным выборкам.

Своя модель наследует `NoveltyDetector` и реализует `fit_windows` и `anomaly_score`. `CentroidDistance` ниже только проверяет, что связка считается до конца.

```python
from industrial_novelty import (
    CentroidDistance,
    ExperimentConfig,
    build_experiment,
    evaluate_model,
)

experiment = build_experiment(ExperimentConfig(window_size=50, stride=25))
model = CentroidDistance().fit(experiment.train.X)
report = evaluate_model(model, experiment, target_fpr=0.01)
report.per_fault
```

Первый вызов `evaluate_model` читает `TEP_Faulty_Testing.RData` (около 800 МБ) и дальше обходит неисправности по одной. Для черновика задайте `max_runs`, чтобы взять несколько прогонов с наименьшими номерами в каждой части эксперимента.

Рабочий пример — ноутбук `notebooks/02_baseline.ipynb`: модель из нескольких строк и общая оценка.

## Проверка идей из Lacuna

Скрипт `scripts/run_lacuna_experiments.py` проверяет калибровку тревог по целым
прогонам, локальные зависимости датчиков, спектральные признаки, NeuTraL AD и
ядерное сравнение недавней истории с нормальным эталоном. Новые ветви сравниваются
отдельно и вместе с текущей моделью CVA + моменты + медленные признаки + EWMA.

Для нейросетевой части нужна дополнительная CPU-зависимость:

```powershell
uv pip install --python .venv/Scripts/python.exe -r requirements-neural.txt
.venv/Scripts/python.exe scripts/run_lacuna_experiments.py
.venv/Scripts/python.exe scripts/summarize_lacuna_experiments.py
```

Быстрый сквозной запуск: добавьте `--max-runs 3 --epochs 2 --seeds 0 --output
data/processed/lacuna_smoke`. Продолжить прерванный расчёт с теми же параметрами
и локальными весами можно через `--resume`.

Параметры и разбиения сохраняются до оценки отказов. Порог по прогонам проверяется
при одинаковом горизонте калибровки и теста: отдельно 500 и 960 отсчётов.
При горизонте 960 из нормального тестового файла выделены 200 прогонов для
калибровки и 300 для проверки. Метки отказов в обучение и пороги не входят.

Результаты: [отчёт](results/lacuna_2026-10-30/report.md),
[все сравнения](results/lacuna_2026-10-30/summary.csv),
[результаты по отказам](results/lacuna_2026-10-30/per_fault.csv).
Источники и исходные гипотезы — в [исследовательской заметке](docs/research/lacuna_ideas_2026-10-30.md).

## Разведочный анализ данных (EDA)

На текущем этапе выполнено:

- Исследование структуры датасета и отдельных прогонов моделирования.
- Проверка пропущенных значений и дубликатов.
- Статистический анализ технологических параметров.
- Визуализация нормальных временных рядов.
- Исследование неисправностей №4 и №6.
- Анализ изменений параметров до и после введения неисправностей.

При исследовании установлено, что разные типы неисправностей могут проявляться как через изменения измеряемых параметров, так и через реакцию управляющей системы.

Также выявлена необходимость учитывать аварийную остановку установки при анализе некоторых неисправных прогонов.

На single-duct AHU сравнены 15 вариантов обнаружения с обучением на норме
и проверена диагностика на отложенных уровнях тяжести. На двух полевых RTU

[Отчёт с математикой, обзором литературы и командами запуска](results/lbnl_sdahu_2026-11-07/report.md).

проверяет перенос трёх методов с переобучением на норме целевой установки
и шесть вариантов их объединения.

[Раннее обнаружение на TEP](results/tep_early_replay_2026-11-07/report.md)
сравнивает непрерывный replay действующих моделей и тесты инноваций
при одном номинальном бюджете ложных тревог на прогон.

[Объединение динамики и инноваций на TEP](results/tep_fusion_2026-11-07/report.md)
